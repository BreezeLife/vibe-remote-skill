# 使用自研 Vibe Remote

这是我们自己的 macOS 开发预览版，直接通过蓝牙读取小米遥控器的 ATVV 音频。
不需要安装 MiRemote、SayAll、BlackHole 或其他桥接应用。0.2 使用 Apple 语音识别，
新增可视化按键配置、工作区草稿和编程工具适配。豆包 / Typeless 虚拟麦克风尚未实现。

## 安装包

从 0.2.2 起，`.pkg` 统一安装到系统应用程序目录 `/Applications/Vibe Remote.app`，
通过 macOS 安装器授权安装。此位置按用户 2026-10-08 的明确要求，替代此前的
`~/Applications` 当前用户安装方案。
先复制需要保留的草稿并退出应用，再双击安装包按提示安装；安装器要求关闭运行中的
Vibe Remote。安装后从上述目录打开应用，保持只运行一份。

当前打包版本为 **0.2.6 / build 9 / macOS 13+**，新增 Codex 一键配置、项目与会话切换、
确认输入和运行中补充任务。保留 Pro 2 实物按键布局、编程工具默认方案、附近遥控器选择、
有限自动重连，以及放大遥控器＋Vibe 字样的图标。实际工具能力仍需按下文逐项检查。
安装包按构建机器的架构生成；Apple Silicon 对应 `arm64`。
应用使用本地 ad-hoc 签名，安装包尚未 Developer ID 签名或 Apple 公证。
安装不自动授予蓝牙或语音识别权限，也不安装其他桥接程序或驱动。

开发者可在仓库根目录生成当前机器架构的安装包和 SHA-256 文件：

```sh
bash scripts/package_macos_app.sh
```

默认输出到 `build/packages/`。可用 `VIBE_PACKAGE_OUTPUT_DIR` 指定其他目录，例如：

```sh
VIBE_PACKAGE_OUTPUT_DIR="$HOME/Downloads" bash scripts/package_macos_app.sh
sudo installer -pkg "$HOME/Downloads/VibeRemote-0.2.6-arm64.pkg" -target /
open "/Applications/Vibe Remote.app"
```

重建时若同名包或校验文件已存在，脚本会拒绝覆盖；选择新的输出目录即可。
也可以双击 `.pkg`，按图形安装器的提示完成管理员授权，无需在终端安装。
打包先在本地临时目录构建，再校验唯一安装域 `LocalSystem` 及解包后的签名。
安装包仅允许安装到系统卷，不提供当前用户目录或其他磁盘选项。安装器禁止重定位到
历史工作目录副本，拒绝覆盖不同 Bundle ID，并检查已有应用版本，避免降级。
系统安装域、退出要求与最低系统版本采用 [Apple Installer Distribution 配置](https://developer.apple.com/library/archive/documentation/DeveloperTools/Reference/DistributionDefinitionRef/Chapters/Distribution_XML_Ref.html)。

## 从源码构建与打开

需要 macOS 13+ 和 Xcode Command Line Tools；在仓库根目录执行：

```sh
bash scripts/test_macos_core.sh
bash scripts/test_macos_speech.sh
bash scripts/test_macos_model.sh
bash scripts/test_macos_hid.sh
bash scripts/test_macos_tools.sh
bash scripts/test_macos_controls.sh
bash scripts/test_macos_integration.sh
bash scripts/build_macos_app.sh
open "$HOME/Library/Caches/VibeRemote/Build/Vibe Remote.app"
```

普通构建将本机架构的 `.app` 输出到 `~/Library/Caches/VibeRemote/Build/Vibe Remote.app`，
无需管理员权限，也不写入系统 `/Applications`。日常安装使用上面的 `.pkg` 流程；
缓存目录的副本仅用于开发检查，避免与已安装的副本同时运行。
应用使用本地 ad-hoc 签名，尚未 Developer ID 签名或公证。
构建器只更新带有自身构建标记的产物；已有其他同名应用
会被保留并报错。可用 `VIBE_OUTPUT_DIR` 指定输出目录，请选择不受 iCloud 同步的位置。
iCloud / File Provider 会在签名后重新附加 Finder 元数据，因此不应在同步目录运行 `.app`。
构建不安装驱动、不修改系统音频设备、不申请辅助功能权限。为保证隐私权限关联稳定，
请从同一目录启动同一份 app，更新前复制需要保留的草稿并退出所有旧版；
重编译后 macOS 可能需要重新授权。不要直接 `swift run`
来做权限验收，完整 app bundle 才包含用途说明和稳定的 bundle ID。

## 第一次使用

1. 唤醒小米蓝牙语音遥控器 2 Pro；首次连接时让它进入配对模式。若其他遥控器桥接应用
   正在运行，先退出它，以免争用连接。
2. 在 **听写** 或 **连接与权限** 点击 **搜索附近遥控器**，允许系统蓝牙授权。
   从列表选择自己的遥控器，应用随即连接并检查音频服务；同名设备可通过短编号区分。
   若系统要求配对，请在 macOS 蓝牙设置中完成，再回到应用重新搜索。
   等待“遥控器已就绪”；仅“连接中”或系统已配对不代表音频可用。
3. 点击 **启用语音识别**，在系统提示中允许。已授权时显示 **语音识别已授权**，
   应用每次开始收音时重新查询实际权限。默认识别语言是普通话，且要求本机识别。
4. 按住遥控器语音键说话，观察音量条、音频时长和草稿。松开后等待“草稿已保留”。
5. 审阅并编辑文字，再点击 **复制草稿**。到目标 AI 输入框粘贴，确认目标后自行发送。

本机不支持所选语言离线识别时，应用会提示且保留已有草稿。你可以更换语言，或显式勾选
**允许 Apple 在线识别** 后重试；在线模式允许音频交给 Apple 语音服务。应用不保存录音
或转写历史，草稿只在内存中，退出前请复制需要保留的文字。

## 发现与自动连接

0.2.5 在两个页面使用同一个设备列表。每次搜索持续最多 20 秒，可以提前停止。
列表合并本次扫描、系统已连接的候选和上次选择记录，按设备身份去重。
“本次发现”来自蓝牙广播；“系统已连接”仅表示系统持有连接，仍需本应用检查音频服务；
“上次选择”可能是离线缓存，不能证明遥控器在附近。信号值只表示接收强弱，不表示距离。
搜索不会自行连接列表第一项，点击某个设备才会开始连接；更换设备前先断开当前连接。

选择会保存在本机，下次打开应用点击 **连接已选遥控器** 即可优先连接同一只。
启动应用本身不扫描、不申请权限、不收音；按钮映射仍需独立完成输入监控及本次验收。
默认启用的自动重连仅用于本次已验证连接在空闲时意外中断，延迟 2、5、10 秒最多尝试三次。
点击断开、关闭自动重连、手动结束收音、收音中断、协议检查失败或系统蓝牙不可用时保持停止。
失败后可唤醒遥控器并手动重新连接；应用不会因重连自动向编程工具发送文字。
**忘记选择** 只删除本应用的连接偏好，不解除 macOS 配对、不改工作区和草稿。

未被唤醒、未广播或正被其他设备占用的遥控器可能无法发现；必要时使用页面的系统蓝牙设置入口。
系统配对确认仍由 macOS 完成。本实现采用 Apple 的
[设备扫描与连接流程](https://developer.apple.com/library/archive/documentation/NetworkingInternetWeb/Conceptual/CoreBluetooth_concepts/PerformingCommonCentralRoleTasks/PerformingCommonCentralRoleTasks.html)，
缓存检索本身不作为可达性或就绪证据。真实发现、配对和两次连续收音仍须用遥控器验收。

## 配置按键

0.2.3 的示意图对应 Pro 2 实物：左上电源、右上语音，中间为方向圆环与 OK；
下方左列依次为返回、主页、菜单，右列为纵向音量 ＋/− 和 TV。
顶部选择哪个工作区，就编辑哪个工作区的动作。实体 HID 键值由同一只遥控器共用，
切换 Codex、Claude 或 WorkBuddy 无需重复学习。无工作区时编辑通用配置。

1. 进入 **连接与权限**，明确授权输入监控，点击 **发现设备** 并选择本次遥控器。
2. 点击 **独占接管并校准**。设备身份或报告描述符不完整、相关接口被占用时保持停用。
   **开始观察** 只用于诊断，不阻止系统接收原始按键。
3. 进入 **按键**，点击遥控器示意图的一个键，再点 **学习此键**，按住约 1 秒后松开。
   单击、600 ms 长按和可选 300 ms 双击可分别配置。语音键保持 ATVV 专用。
   未锁定选择时，按键页只高亮/选择；锁定或离开此页后才执行已启用的动作。
4. 在本次独占连接中验证确认键不穿透为系统回车、音量不重复，语音键仍可收音。
   返回连接页确认验收并点击 **启用已配置动作**。重连、休眠或撤权后需要重新验证。
5. 电源打开工作区选择、菜单打开动作菜单；方向键移动选择，OK 确认，返回关闭。
   菜单中的控制优先于普通工具动作。菜单栏可随时暂停并释放设备。

原生配置存于 `~/Library/Application Support/Vibe Remote/settings.json`，与 Python 配置
格式不同。导出、复制配置不含草稿；导入先校验，已有工作区会保留，发生 ID 冲突的不同
目标分配新 ID，避免旧草稿被分配到新目标。上一份有效配置保存在 `settings.previous.json`。
**恢复本方案默认动作** 仅恢复当前工作区动作，保留已学习键值和工具快捷键。
旧配置会继续使用原来的通用动作，首次编辑工作区动作时才生成独立方案。
含工作区方案的新配置需要 0.2.3 或更新版本；旧版会拒绝不认识的字段，降级前请保留备份。

## Codex 一键配置与会话操作（0.2.6）

1. 在 **编程工具** 顶部点击 **一键配置 Codex**。应用检测本机 Codex 桌面版、读取项目与
   会话目录，并准备默认按键；此时不会打开会话、输入文字或发送测试消息。
2. 选择项目，再点击一个会话。应用为这个会话保存独立工作区，打开对应会话并尝试聚焦
   输入框。顶部第二行也可切换项目与会话；项目选择器只筛选列表，选中会话后才改变目标。
3. 展开 **安装与上次检查结果**，分别查看应用安装、会话目录、会话定位、输入框与提交结果。
   **检查所选会话** 只重新定位和聚焦，不输入或提交文字。缺少辅助功能权限时，按页面提示
   到系统设置授权，再回到应用检查。
4. 先完成上文的 HID 独占接管、实体按键学习和本次连接验收，再启用遥控器动作。
   一键配置不会代替这些步骤，也不会自动授予系统权限。

已有手动工作区、草稿、自定义按键与快捷键会保留。会话目录在本次读取后供选择，
只有明确选择的会话才保存为工作区；以后可重新点击一键配置刷新目录。每个会话有独立的
内存草稿，不通过 **复制工作区** 另建同一会话；要使用其他会话，请从会话列表选择。
含 Codex 会话配置的导出文件需要 0.2.6 或更新版本，降级前请保留旧版配置备份。

一键配置创建的 Codex 工作区使用以下按键；已有手动工作区沿用原方案，除非你主动更改：

| Pro 2 实体键 | Codex 会话默认动作 |
| --- | --- |
| 上 / 下 | 当前项目的上一个 / 下一个会话 |
| 左 / 右 | 上一个 / 下一个项目，优先回到本次使用过的会话，否则选择该项目第一个会话 |
| 语音 | 按住说话，松开保留为当前会话的未发送草稿 |
| OK | 第一次确认输入并预览完整内容；确认页中再按一次明确提交 |
| 主页 | 聚焦所选会话的输入框 |

其他按键沿用下表的固定用途。项目或会话到达列表边界时停止，不循环跳转。
切换时保留各自草稿；收音、整理识别结果或执行工具操作期间暂时锁定目标。

**确认输入** 会保留目标输入框已有文字、追加当前草稿并读回核对。目标、控件和设备检查
通过后，才展示完整内容确认页；先看清会话和文字，再按一次 OK 或点击确认按钮。
第一次 OK 不直接提交。文字或目标变化、录音开始、设备状态变化都会取消待确认操作。
如果任务正在运行且实时识别到可用的 **Steer / 补充输入** 控件，优先使用它，确认页会显示
**补充当前任务**；普通发送显示 **确认发送**。不能确认状态或找不到所需控件时保留草稿
和已插入文字，请检查目标输入框后手动发送；不要反复粘贴同一段文字。

提交后草稿仍保留，原草稿不能再次提交；下一条指令请先清空草稿，再按住说话。
写入或提交的结果不确定时，重复 OK 会被阻止。请先检查 Codex 实际内容和任务反馈，
必要时手动处理，不要靠重复按键猜测是否成功。

页面显示的是上次检查记录，选中会话不等于实际窗口已定位，目录信息也不能证明任务正在
运行或输入框可用。每次输入和提交仍重新检查当前目标，应用版本或界面变化可能导致检查失败。

### Codex 实机测试指引

当前开发验证使用隔离的模拟服务与源码界面渲染。Codex 的真实窗口受本次 UI 自动化访问
限制，尚未通过自动化实机检查；这些测试也不证明遥控器按键、语音或真实提交已可用。
请由你在实际窗口逐项验收，应用不会自动发送测试消息：

1. 检查连接、语音识别、输入监控与辅助功能权限。确认独占后原始按键不穿透、音量不重复、
   语音仍能收音，并在连接页启用已配置动作。
2. 在同一项目选择两个已有会话，用上 / 下分别打开；观察 Codex 主内容区标题与输入框。
   若有第二个项目，再用左 / 右检查跨项目定位与返回。
3. 在第一个会话按住说一句、松开检查草稿；在第二个会话重复一次，再切回第一个会话，
   确认两份草稿各自保留且未发送。
4. 用你确实准备提交的内容按一次 OK，检查实际输入框及完整内容确认页；先取消一次，
   确认没有提交。再次准备确认后，只有你第二次按 OK 或点击确认按钮才提交。
5. 若当前任务正在运行，检查确认页是否明确显示 **补充当前任务**，确认后观察 Codex 的
   实际反馈。没有可靠控件或状态时，应提示保留文字、改为手动操作，不能把提示当作提交成功。

## 手动工作区：Codex、Claude、WorkBuddy 默认按键方案

进入 **编程工具**，在对应应用下点击 **使用默认方案添加工作区**。
已有工作区可在其按键方案卡片点击 **应用默认方案**；应用前会说明替换范围，保留绑定、
草稿及已学习的实体键值，工具快捷键恢复为默认辅助功能控件方式。两个 WorkBuddy
应用身份分别建立工作区，共用同一套默认按键习惯。

| Pro 2 实体键 | Codex / Claude / WorkBuddy 默认动作 |
| --- | --- |
| 电源 | 选择工作区 |
| 语音 | 按住说话，松开整理为未发送草稿 |
| 上 / 下 | 滚动输出；持续按住连续滚动 |
| 左 / 右 | 上一个 / 下一个已登记工作区 |
| OK | 选择器内确认；草稿已插入后预览发送，再明确确认 |
| 返回 | 单击取消；长按停止已确认正在运行的当前任务 |
| 主页 | 聚焦绑定工具的输入框 |
| 菜单 | 打开动作菜单，可选择插入草稿、发送等动作 |
| TV | 打开本工作区配置的预览地址 |
| 音量 ＋ / − | 调节系统音量；支持持续按住 |

默认不启用双击。三种工具采用相同的遥控器操作习惯，目标分别绑定到各自工作区，
需要差异时点击 **编辑本工作区按键** 调整。预设不包含猜测的 HID usage 或键盘快捷键；
实体按键学习、辅助功能绑定和实际能力验证仍按下文完成。仅能报告短按的实体输入不会
执行长按动作，重新学习并确认长按后才启用。更换工作区会丢弃上一工作区尚未完成的按键事件。

## 手动绑定 Codex、Claude、WorkBuddy

以下适用于从应用卡片添加的手动工作区；一键配置的 Codex 会话采用上面的自动定位与当次检查。

截图若提示「辅助功能尚未授权」，先到 **连接与权限 → 启用辅助功能**。
在 macOS **系统设置 → 隐私与安全性 → 辅助功能** 中开启你实际运行的 Vibe Remote，
然后回应用点击 **刷新**。列表没有应用时，用「＋」选择实际安装位置的 `.app`。
不要把输入监控授权当成辅助功能授权，两者用途不同。

已经出现在顶部工作区选择器中的项目不必重复添加。工作区设置里的字段这样填：

| 字段 | 用途与示例 |
| --- | --- |
| 工作区名称 | 自己识别用的名字，如 `Codex · VibeRemote`；不是项目目录 |
| 预览地址 | 可留空；有网页项目时填真实预览网址，如 `http://localhost:3000` |
| 精确会话入口 | 可留空；已有真实链接时才填 `codex://threads/<真实ID>`，不能替代输入框学习 |

点击 **保存工作区信息** 后继续向下滚动，找到 **绑定输入与会话**。
初次学习时，这个工作区的 Vibe Remote 草稿必须为空；已有草稿请保留并另建工作区。

1. 在 **编程工具** 为已安装应用添加工作区；两个 WorkBuddy 按 Bundle ID 分开。
   也可选择本机其他 `.app`。安装存在仅表示可尝试绑定，不代表输入或发送已通过。
2. 授权辅助功能，选择工作区。点击 **学习输入框** 后在 5 秒内切到工具并点击 AI 输入。
3. 点击 **学习会话标题** 后，把鼠标停在同一窗口主内容区当前任务的独有标题上。
   侧栏中仍存在的旧会话名、隐藏控件、普通 shell、无法唯一定位的元素会被拒绝。
4. 点击 **测试聚焦**。回到听写页生成或编辑草稿，点 **插入草稿**。应用保留目标已有文字，
   通过 AX 写入并读回核对；不支持 AX 写入时请显式复制后手动使用。
5. 分别学习真实的 **发送** 和 **停止生成** 控件。停止控件可能仅在任务运行时出现。
   要发送，先插入当前草稿，再点 **预览发送**；检查显示的目标和完整内容后确认。
   文字、目标、设备授权或录音状态变化都会取消确认。没有明确控件/状态时不执行。
6. **停止当前任务** 只操作已识别且正在生成的绑定任务。触发操作后若结果未观察到，会明确
   提示检查，不能据此认定已完成，也不会自动重试发送或停止。

当前版本中，鼠标点击 **预览发送** 也要求遥控器已 **独占接管**，并在连接页完成本次
「按键不穿透且语音正常」的验收勾选。仅配对、连接音频或授权辅助功能不够。
发送和停止控件须分别学习，目标任务需处于可确认的空闲状态，当前草稿需先经 **插入草稿**
写入并验证。手动粘贴不建立这项验证。工具学习会暂停映射，使用实体遥控器操作前，回
连接页重新点击 **启用已配置动作**。

如果目标工具没有暴露可写输入框、同一主内容区的当前会话标题或可识别的发送/停止控件，
当前适配可能无法完成；填写网址不能解决。此时可先 **复制草稿 → 到目标工具粘贴 → 手动发送**。

每个工作区及“未绑定草稿”分别保存内存文字，切换不会搬移草稿；收音和识别整理期间锁定目标。
应用升级后旧 AX 绑定失效，需要重新学习。快捷键是已知动作的可选实现；发送和停止还要求
控件公开与配置一致的快捷键，缺少证据时请恢复默认 AX 方式。录制期间暂停遥控器映射。

Codex 可配置 `codex://threads/<id>` 并显式打开；**在 Codex 预填新草稿** 是独立操作，
使用官方 `codex://new`，不会自动发送或替换原工作区绑定。
CLI、截图附件和指针功能不属于本版已实现的原生动作。

## 操作边界

- 松开语音键会结束音频，等待最终识别；不会向任何应用自动发送。
- 一段听写完成后，下一段追加到已有草稿。取消只撤销当前这段，保留此前文字。
- 正常松开语音键可继续下一次听写；手动点击取消/结束后，本版会断开连接，以避免
  同一次长按的重复事件重新启动录音。再次点击连接后继续。
- 0.1.1 起，权限或识别失败会在连接区域显示具体原因，继续显示收到的音频时长与音量，
  保留蓝牙连接。此时标注「收音中 · 未转写」；松开语音键后处理提示，再按住重试。
  同一次按住期间不会自动重启识别，也不会自动切换为在线识别。
- 收音或等待识别期间，编辑和复制暂时停用，避免后续结果覆盖手工修改。
- 断连会结束收音；如果没有最终结果，会保留收到的部分文字并提示。可检查后手动修订。
- 按键映射默认暂停；观察模式仍可能触发原始 macOS 按键。只有完整独占并验证后才启用映射。
- 工具操作需要辅助功能、具体工作区绑定和当次检查，不盲目粘贴或按 Enter。
- 本版不暴露豆包可选择的虚拟麦克风，也不向普通终端发送或注入 Ctrl+C。

## 排障与验收

连接不到：检查系统蓝牙，唤醒遥控器后点击搜索。若列表只有“上次选择”，先检查系统配对
和遥控器电量；必要时完成配对后重新搜索。应用只连接你选择的设备，只有音频协议检查通过
才会显示就绪。空闲断线的自动重连有次数上限，手动停止和收音中断需要再次点击连接。

没有文字：先看音量与收到的音频时长，再看语音授权/语言支持。若只有音频没有转写，
这代表音频链路与识别链路的状态不同，不能据此认定蓝牙无效。权限被拒绝后，去
系统设置 → 隐私与安全性 → 蓝牙 / 语音识别允许 Vibe Remote，再重试或重开 app。

一按语音键就显示「已手动停止」：0.1.0 会把识别启动失败误当作手动停止，主动断连。
请更新到窗口右上角标明 **0.1.1 或更高** 的版本，并确保只有一份 Vibe Remote 在运行。
新版会展示识别错误，便于区分权限、语言支持和音频问题。主动点击取消/结束仍需重连；
连续 8 秒未收到有效音频或单段达到 90 秒也会停止，但会明确显示超时原因。

实机验收至少覆盖：连续两次按住/松开、取消并保留旧草稿、收音时断连、显式复制、
离线模式不支持时提示、在线模式只在勾选后启用。软件测试结果与实机进度见 [TASKS](../TASKS.md)。

开发测试：本机仅装 Command Line Tools 时使用上述测试脚本；完整 Xcode 环境也可运行
`swift test --package-path apps/macos --disable-sandbox`，两种方式执行同一组核心测试。
`test_macos_model.sh` 使用 fake 服务运行真实模型的按键、权限、识别失败和草稿回归，
不创建真实蓝牙连接或识别器，不弹系统授权，不接触剪贴板。
