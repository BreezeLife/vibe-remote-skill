# Vibe Remote 0.2 — 可视化按键与编程工具

状态：用户于 2026-10-05 确认桌面优先方案，开始实施。Asia/Shanghai。

## 目标与范围

用户要求参考 SayAll，在我们的原生应用中配置遥控器按键，并支持 Codex、Claude、
WorkBuddy 等编程工具。保留当前 ATVV → Apple Speech → 内存草稿链路。

按已确认的桌面应用优先方案实施。终端 CLI 保留独立适配接口，现有 Python/tmux helper 继续使用；
首版不把普通终端窗口当成可安全发送的 AI 输入。若用户选择桌面与 CLI 同时交付，
需要把精确 pane/session、AI 进程及输入状态观测加入同一验收范围。

完成判据：用户能在界面选择实体键、学习实际输入、配置动作、选择编程工具并测试。
实体按键能执行已启用的动作；草稿目的地可见，发送只发生在显式操作和实时校验后。
配置页面可用、硬件捕获成功、工具动作验证成功分别记录，不能相互替代。

## 路线选择

| 路线 | 收益 | 代价 |
| --- | --- | --- |
| 统一动作 + 工具适配（推荐） | 按键习惯稳定，应用差异由适配器处理，可逐项验证目标和动作 | 需要输入框绑定及动作状态检查 |
| 纯快捷键配置 | 配置直观，通用组合键容易覆盖 | 快捷键本身不能证明当前任务、输入框或发送状态 |
| 每个工具深入接入独立 API | 有接口时可获得精确会话与运行事件 | 需要分别管理连接与授权，不能假设能接管已有桌面会话 |

采用第一条。快捷键是工具动作的一种实现方式，经过同样的目标校验；后续有明确官方
接口的工具可增加独立适配器。不会用任意 shell 命令充当通用动作。

## 页面与操作

窗口使用原生侧栏：**听写、按键、编程工具、连接与权限**。现有听写内容保留。

### 按键

- 左侧是自行绘制的遥控器示意图；点击图中按键，在右侧编辑动作。
- 提供“按一下选择此键”和编辑锁定，实体按键高亮；学习期间只记录输入，不执行动作。
- 单击为默认；长按可选。双击为可选扩展手势，启用时显示短按等待时间。
  默认长按 600 ms、双击窗口 300 ms；实际脉冲型按键不开放无法识别的长按。
- 动作包括工作区选择、聚焦目标、复制/插入草稿、明确发送、取消、停止任务、
  切换已登记工作区、滚动、打开预览和系统音量。
- 快捷键可用修饰键/按键选择器编辑，也可在点击“录制”后短时录入；可取消并保留旧值。
  快捷键仅作为已知语义动作的工具端执行方式，没有独立的任意快捷键动作。
  发送/停止快捷键只能作为对应语义动作的实现，不能绕过状态校验。
  Return/Enter、Cmd-Return、Esc、Ctrl+C 等提交或中断按键不能伪装为聚焦等普通动作。
  动作语义无法通过工具测试确认时保持禁用，导入的设置遵守相同限制。
- 同一份全局按键意图用于所有工具；每个工具配置该意图的执行方式。支持恢复默认、
  复制方案和本机 JSON 导入/导出，导入先验证再写入，不覆盖无关配置。
- 语音键保持 ATVV 专用，不另行合成 Fn 或重复开关录音。音量默认保持系统音量意图。

### 编程工具

内置工具卡片：Codex、Claude Desktop、WorkBuddy，并允许选择任意本机 `.app`。
卡片显示真实安装状态、应用图标/版本、选定工作区及每项动作的检查结果。

本机元数据已核对：

| 应用 | Bundle ID | 版本 |
| --- | --- | --- |
| Codex（当前包名为 ChatGPT.app） | com.openai.codex | 26.930.21537 |
| Claude | com.anthropic.claudefordesktop | 1.25927.0 |
| WorkBuddy | com.tencent.workbuddy.mac | 5.5.3 |
| WorkBuddy AI | com.workbuddy.workbuddy-ai | 5.6.2 |

两款 WorkBuddy 单独列出，不按显示名称合并。安装存在不代表焦点、输入或发送已经可用。

工具绑定流程：选择应用 → 选择/记录窗口与会话标识 → 用户定位输入框并学习 →
测试聚焦 → 测试插入。发送和停止控件分别校准、分别验证。
状态区分“未安装、可打开、待绑定、上次测试通过、当前检查失败”；保存的测试结果
不能直接作为一次执行的许可。应用更新导致绑定失效时提示重新学习。

Codex 可选绑定明确的 `codex://threads/<id>`；“预填新会话草稿”是独立显式动作，
使用官方支持的 `codex://new`，不会被用作找不到原会话时的替代。
Claude/WorkBuddy 先通过实际输入框及控件绑定接入，不猜测通用发送/停止快捷键。

### 连接与权限

分别显示 Bluetooth/ATVV、Speech、输入监控、辅助功能、选中 HID 设备及映射状态。
只有用户点击相应启用按钮时请求权限；服务初始化不请求权限或接管设备。
配置页提供暂停映射和释放设备入口，菜单栏也能随时停止接管。

## 按键输入与手势

HID 与蓝牙音频独立。IOHID 先按候选 VID/PID 筛选，再由用户明确选择设备。
候选身份不能代替实际按键校准。学习 usage page、usage、report ID 和描述符匹配信息；
运行期 cookie/registry ID 只用于当前连接，不作为跨机器键位标识。
不记录序列号、蓝牙地址、输入内容或音频。

观察模式用于诊断，不能声称屏蔽系统原始按键。真正启用动作前，对明确选中的设备
尝试独占打开，并验证其相关 HID 接口已受控；失败时保持动作关闭，不退化为全局
F5/Enter 拦截。必须实测原始 OK/Enter、音量等不再穿透或重复执行，以及 ATVV 仍正常。
初始校准不要求用户打开 AI 输入框，并明确原始系统行为是否仍可能发生。

手势归一化在 Core 中执行：忽略重复 down、按 up 结算单击；长按触发一次后抑制单击，
双击启用时等待窗口并抑制两个单击。只允许滚动和音量连发。断连、休眠、撤权、
切换设备或修改映射时取消计时器及待处理手势，不能补发点击。
若 HID 只提供脉冲或没有可辨别事件，该键只显示实际支持的手势或标记不可用。

## 草稿与执行规则

- 录音前锁定工作区；采音或识别收尾期间不切换目标。
- 每个工作区保留独立的内存草稿。切换回来能继续编辑；不把旧工具的文字自动归到新工具。
  首次选择工具也不会接管未绑定的旧草稿；迁移已有文字须由用户明确选择复制到目标工作区。
- 用户选定的工作区持续有效；切换到浏览器预览不会改变 AI 目的地。
- 激活后重新读取前台进程与窗口。请求激活成功不能直接推定聚焦成功。
- 插入前验证窗口/会话、可编辑的非密码输入框及当前目标；保留原有输入，插入后读回验证。
  AX 不支持或绑定有歧义时，保留草稿并提示手动复制，不盲目向未知位置粘贴。
- 发送必须同时确认：遥控器有效、绑定目标一致、当前会话与 AI 输入已识别、
  收音和识别均停止、存在已审阅草稿、AI 可接收、发送控件有效。
  发送预览显示目标和待发送全文，用户确认这份预览后才执行；目标或文字变化使确认失效。
- 停止必须确认当前绑定任务正在运行及其停止控件。通用 Chromium 的页面 stop
  不是停止 AI；普通 shell、未知状态和无法确认的工具动作均阻止执行。
- 发送与停止不可连发；一次动作完成前串行处理后续请求，执行后重新观察结果。
- 工具页可以保存尚未可用的配置，但相应动作显示明确失败原因并保持关闭。
  不把一个工具配置成功描述为所有工具功能已验收。

## 数据与模块边界

原生配置保存在 `~/Library/Application Support/Vibe Remote/settings.json`，带独立格式名
和 schema 版本，原子写入并保留有效旧配置。导出只包含配置，不包含草稿、音频或会话正文。
它不是既有 Python skill 的配置格式；不能直接覆盖其 config.local.json。
导入拒绝未知动作、任意脚本和不受支持的 URL scheme；预览只接收明确配置的 HTTP(S)
地址，Codex 导航仅接收已定义的会话/新草稿入口。导入不会启动应用或执行动作。

Core：按钮/动作/工具配置、手势状态机、工作区草稿、执行条件，保持可注入时钟和纯数据测试。
App：HID 服务、配置存储、工具适配/AX 观测、动作协调器、SwiftUI 配置页面。
原有 BluetoothService/SpeechService 保留音频职责；不把配置和工具执行塞入 ATVV 协议层。

预计影响：新增 Core 配置/手势/执行策略及测试；新增 App HID、工具适配、配置存储和
配置页面；调整 RemoteModel 的工作区草稿接入与 RemoteView/VibeRemoteApp 导航；
补充权限说明、相关回归、文档、skill 的原生功能边界和版本/安装包。

## 实施与验收顺序

1. 配置模型、持久化、手势和执行条件；假事件覆盖重复、长按、双击、断连与撤权。
2. 可视化按键/工具页面；导入损坏文件、未知 schema、切换草稿与恢复默认均保留用户数据。
3. HID 校准和独占接管；真实遥控器验证键位、释放、系统抑制及语音链路共存。
4. Codex 先完成激活、精确目标绑定、草稿插入、发送/停止能力的逐项测试；
   同一接口扩展 Claude 和两款 WorkBuddy，并记录每项实测结果。
5. 回归既有 0.1.1 的语音失败不断连、取消恢复、连续听写和全部相关检查；生成 0.2 安装包。

自动化测试使用 fake HID/AX/时钟/执行器，不申请系统权限、不往真实工具发送测试消息。
物理和第三方应用测试由实际交互确认。未通过的能力不能在发布记录里标为完成。
